## Hybrid delivery decision — authoritative

The final icon package is **hybrid SVG/PNG**, not SVG-only.

Rules:

- small functional artwork uses simplified SVG when added raster detail has no visible benefit;
- detailed artwork uses PNG where material, lighting, texture, or painted detail is visibly superior;
- one canonical may use SVG at smaller sizes and optimized PNG variants at larger sizes;
- raster-capable detailed artwork starts from a high-resolution master, initially around 1024×1024 or larger if visual testing justifies it;
- each emitted PNG size must be reviewed and may require size-specific optimization rather than blind downscaling;
- the SVG→PNG crossover is deliberately **not frozen yet**;
- determine that crossover through visual A/B comparison at representative sizes;
- embedded-PNG-in-SVG is not the default delivery mechanism;
- `style_class` controls visual/review language, not file format.

No delivery manifest exists yet by design. Add structured delivery metadata only if the crossover pilot shows that class/family rules are insufficient and per-canonical exceptions are required.

The current `tools/build-icons.py` scalable-only staging behavior remains a development scaffold and must be upgraded before final v1 packaging.

## Hero visual constraints

Hero artwork should preserve:

- strong application identity before decorative detail;
- original Witcher-inspired material treatment rather than copied vendor/game assets;
- varied silhouettes instead of one repeated medallion/container;
- controlled red;
- blackened iron, weathered steel, leather, parchment, restrained magical accents;
- no font dependency for identity-critical marks;
- no external network references in release SVGs;
- high-resolution raster masters with no accidental upscaling.

Candidate comparison sizes:

- 32 px
- 48 px
- 64 px
- 96 px
- 128 px
- 256 px
- 512 px

These are **test sizes**, not a frozen PNG ladder.
