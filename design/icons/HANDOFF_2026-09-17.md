- high-detail forged Witcher treatment is authoritative for Hero/Application artwork;
- blackened/weathered steel, worn silver, authored damage, real depth/lighting and controlled Witcher-red recess/emissive accents are the target;
- flat/cartoon simplified Hero redraws are rejected;
- Hero SVG is **optional**;
- if a faithful practical SVG cannot be produced, PNG-only is explicitly valid;
- a Hero SVG must preserve the same subject, silhouette, composition, palette hierarchy, lighting and material identity as the approved raster master;
- an SVG containing an embedded PNG does not count as successful vector reconstruction;
- the accepted vector-specific facet/mosaic character is allowed when it comes from faithful reconstruction and does not hurt readability;
- edge-aware smoothing remains an experimental option only; for Dolphin it was visually rejected because it looked softer/muddier and lost material detail.
- **current reviewed Hero delivery baseline: SVG at 32/48/64/96/128/256/512 px; PNG at 1024 px**;
- this boundary is visually accepted for Dolphin and the replacement terminal-forward Kitty; materially different future Heroes may deviate only after explicit native-size review.

### PNG→SVG reconstruction tooling

Production experiment tool:

`tools/reconstruct-hero-svg.py`

Tests:

`tests/test_hero_svg_reconstruction.py`

The tool now supports:

- SLIC perceptual superpixel segmentation;
- source-derived color measurement;
- KMeans palette clustering;
- real SVG polygon reconstruction;
- compact relative path serialization;
- Scour optimization;
- brilliance presets: `off`, `mild`, `balanced`, `punchy`;
- optional edge-aware surface smoothing;
- default same-color facet seam overlap: **1.25 analysis pixels**;
- default source-alpha-derived **opaque vector underpainting** below the facets;
- 256/512 diagnostic rendering and engineering metrics.

The underpainting is mandatory for current faceted Hero candidates because ordinary per-polygon antialiasing otherwise lets desktop background leak through thousands of internal facet seams, especially on light backgrounds.

### Locked semantic-convention rule

Project-owner direction: **use established desktop icon conventions wherever practical.**

The Witcher treatment should change material, finish, construction, palette and secondary ornamentation, but should not gratuitously replace a universally learned symbol. Examples include folder silhouettes for folders, gears/cogs for settings, speaker/headphones/microphone metaphors for audio, magnifying glass for search, document shapes for files, and standard transport controls for media.

For families, approve one strong semantic base and derive variants from it rather than redesigning the semantic object from scratch for every canonical. Folder family is the reference example: one approved Witcher folder master, then Home/Downloads/Documents/Music/Pictures/etc. through secondary differentiators.

This rule was added to `design/icons/ART_DIRECTION.md` in commit `1cc4cd8e`.

### Alpha / transparency lessons that must not be lost

A previous Kitty attempt used corner-connected near-black flood removal and accidentally erased **77,393 interior pixels** because blackened forged regions connected to the exterior background.

Never repeat that workflow.

Rules now:

- do not use near-black flood-fill background removal for dark forged Hero artwork;
- prepare alpha from a controlled silhouette/mask;
- keep internal blackened metal opaque;
- use the reconstructor's vector underpainting by default;
- verify both dark and light surfaces;
- treat light-surface washout as a likely alpha/coverage bug before changing color/style.
