## Hybrid delivery decision — authoritative

The overall icon package may remain **hybrid SVG/PNG**, but Hero/Application delivery is now explicitly **fidelity-first**.

- Glyph and many Emblem families may use simplified SVG where simplification is visually appropriate;
- Hero SVG is optional and must look like the same approved high-detail artwork, not a flat/cartoon reinterpretation;
- Hero PNG is the visual source of truth for the current production-quality workflow;
- a Hero canonical may ship PNG-only at all approved sizes;
- there is no requirement to force SVG at small Hero sizes;
- if a practical PNG→SVG reconstruction passes visual fidelity and size/complexity checks, it may be used and then tested for a real crossover;
- if it does not pass, use PNG rather than lowering the Hero style bar;
- embedded-PNG-in-SVG does not count as successful vector delivery.

See `design/icons/HERO_STYLE_LOCK.md` for the authoritative rule.

The current `tools/build-icons.py` scalable-only staging behavior remains a development scaffold and must not dictate Hero artwork format.

## Valid Hero vector/crossover experiment

A Hero crossover candidate now requires **both** a production-quality raster master and a fidelity-passing vector reconstruction.

Required process:

1. start from the accepted high-detail PNG identity;
2. attempt a PNG→SVG reconstruction using visual segmentation, clean path fitting, layered gradients/masks/highlights and final SVG optimization;
3. compare SVG vs PNG first at 256 and 512 px;
4. reject the SVG immediately if subject/silhouette, composition, dominant colors, depth, lighting or material language are visibly different;
5. if it fails, record PNG-only for that candidate rather than inventing a crossover;
6. only if it passes, compare 32, 48, 64, 96, 128, 256 and 512 px at 100% native size on the standard five surfaces;
7. record SVG file size/complexity as part of acceptance;
8. repeat on a materially different Hero if a class-wide default is still desired.

The crossover criterion remains visible quality at normal viewing scale, but **fidelity to the same artwork comes first**.

## Project-owner verdict — smoothing rejected, V1 facets retained

The project owner prefers the original faceted Dolphin reconstruction over edge-aware smoothing.

- V1 facet geometry/detail is the new baseline;
- the smoothing mode remains an experimental tool option only and must not replace V1 by default;
- smoothing was judged too soft/muddy because it removes useful material detail.

A new fidelity issue was identified: both SVGs have lower perceived **brilliance** than the PNG. Analysis confirms that average brightness is already matched, while the SVG compresses luminance contrast, bright silver highlights, and high-end chroma.

The reconstructor therefore now supports optional **Lab palette brilliance compensation** without changing any geometry. Presets: `off`, `mild`, `balanced`, `punchy`.

## Facet-seam alpha correction milestone

Review of the first seven-size package found that `stroke-width=0.55` left anti-aliased transparency between the thousands of facet polygons. Dark backgrounds hid it, while the light edge-case surface exposed it as a grey/washed-out vector.

A parameter sweep selected **`1.25` analysis pixels** as the new default facet seam overlap.

This does **not** smooth the artwork and does **not** change the accepted `punchy` palette. It only overlaps adjacent same-color facet boundaries enough to prevent background leakage.

The previous seven-size review package is therefore superseded for crossover judgment. Regenerate it before recording per-size format decisions.

Consequences:

- **withdraw the previous combined Dolphin+Kitty crossover verdict**;
- Kitty's seven-size package and 256 tie-break are invalid until regenerated;
- Dolphin must also be re-rendered with the new opaque vector underpainting before the earlier <=128 / 256 / 512 verdict becomes final;
- the reconstructor now emits a source-alpha-derived dark vector underpainting below facets by default.
