## Hybrid delivery decision — do not lose this

The final icon package is **not SVG-only**.

The intended v1 delivery model is hybrid:

- simplified SVG for sizes where additional raster detail has no visible benefit;
- detailed PNG variants for sizes where raster material/lighting/texture is visibly superior;
- the same canonical may use SVG at small sizes and PNG at larger sizes;
- raster variants originate from a high-resolution detailed master (initial target around 1024×1024) and each emitted size must be reviewed/optimized rather than accepted as a blind resize;
- the SVG→PNG crossover is deliberately **not frozen yet** and must be established visually by A/B testing;
- embedded-PNG-in-SVG is not the default strategy because it does not solve per-size art direction.

The matrix `style_class` remains a visual/review classification, not a delivery-format switch. No delivery manifest is added yet because the crossover and exception model have not been established. If per-canonical exceptions are needed after the pilot, add structured delivery metadata then.

The current `tools/build-icons.py` scalable-only staging behavior is a development scaffold and must be upgraded before final v1 packaging.
